Visão Geral e Objetivo

Construir o site institucional da MB Consultoria e Treinamento Neves para divulgar a empresa e apresentar seus serviços. O site funciona como uma vitrine: atrai empresas e alunos, mostra os cursos e treinamentos, e gera contato via WhatsApp.

Numa segunda fase, ganha uma área administrativa protegida por login, onde o responsável cadastra, edita e remove cursos e adiciona fotos das turmas — sem tocar no código.

Mensagem-chave do site: “Segurança do trabalho sob controle.”
02

Escopo

Dentro Faz parte do sistema

  • Catálogo de cursos por categoria, com filtro e detalhes
  • Galeria de fotos das turmas (prova social)

Fora Não faz parte (por ora)

  • Emissão automática de certificados

Arquitetura do Sistema

Arquitetura desacoplada: o frontend nunca acessa o banco diretamente — todo pedido passa pelo backend, o “porteiro” que valida tudo.

Públicovisitante
Adminvocê
Frontend — React + TypeScript (SPA)
Vitrine pública · Painel admin (só logado)
HTTPS · JSON
Backend — Spring Boot · API REST
Spring Security (login) · regras de negócio · validações
Banco PostgreSQL
cursos · turmas · usuário admin
Armazenamento de imagens
foto no serviço · link no banco
O React nunca fala direto com o banco. Essa separação já é a primeira camada de segurança.

6.1 · Área administrativa (rota protegida)

A área de cadastro não é um app separado: é uma rota protegida dentro do mesmo frontend, liberada só após o login — como entrar por dentro da vitrine para trocar a roupa do manequim.

🌐 Público (qualquer um)🔑 Restrito (só com login)
/  (home)/login  → entrada
/cursos/painel  → CRUD de cursos
/turmas       + upload de fotos
/contato
Esconder a rota no frontend não é proteção. A segurança real está no backend: o Spring Security recusa qualquer pedido à API sem um token (JWT) válido. A “porta” pode ser de vidro — o que segura é a “fechadura”.

Plano de SegurançaDefesa em camadas

Nenhum sistema é 100% seguro. O objetivo é empilhar proteções até tornar o ataque inviável — e todas vêm de frameworks maduros, nunca de segurança “na mão”.
CamadaProtege contraComo
HTTPSInterceptação de dadosCertificado SSL (cadeado no navegador)
Spring SecurityAcesso não autorizadoSó admin logado acessa o cadastro
Hash BCryptVazamento de senhasSenha nunca em texto puro
Token JWTFalsificação de sessão“Crachá” temporário e assinado
ValidaçãoDados maliciososBackend recusa dados fora do formato
Spring Data JPASQL InjectionConsultas parametrizadas
React escapeXSSNeutraliza scripts injetados por padrão
CORSAbuso da API por terceirosSó o site oficial chama a API
Rate limitingForça bruta no loginLimita tentativas por tempo
Menor privilégioEscalada de acessoCada parte só acessa o necessário

Fases do ProjetoRoadmap

Vitrine (frontend)

Adaptar o protótipo React, inserir dados reais (WhatsApp, fotos, NRs, cargas horárias) e publicar o site estático — catálogo ainda “fixo”.

Backend e Cadastro (dinâmico)

Criar a API em Spring Boot + PostgreSQL, login seguro (Spring Security + JWT), o CRUD de cursos e o gerenciamento de fotos, e conectar o React à API.

Publicação e Segurança final

Configurar HTTPS, CORS e rate limiting; testes de segurança e responsividade; deploy (hospedagem) e monitoramento.

Glossário

Frontend
A parte visível do site — o que o visitante vê.
Backend
O “cérebro” nos bastidores, que processa e valida os pedidos.
API REST
A “linguagem” pela qual frontend e backend conversam (via JSON).
SPA
Site que carrega uma vez e atualiza sem recarregar a página.
CRUD
Create, Read, Update, Delete — as 4 operações sobre os dados.
JWT
Token (crachá digital) que prova que o usuário está logado.
Hash (BCrypt)
Transformação irreversível da senha, para guardá-la com segurança.
ORM / JPA
Ferramenta que liga o código Java às tabelas do banco.
TypeScript
JavaScript com tipos — declara o tipo de cada dado, como em Java/C#, e avisa erros enquanto você escreve.
